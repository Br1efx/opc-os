# S9 · 用 briefx-bot 轮询 GitHub

## 目的

用机器人账号 `briefx-bot` 的 `gh` 轮询 opc-os。Issue 评论里 @ 机器人后，1 分钟内出现工单。

## 环境

- 仓库 `Br1efx/opc-os`
- 本机 `gh` 已登录，账号是 `cursor`，不是 `briefx-bot`
- `OPC_GITHUB_TOKEN` 未设置
- 没有 `briefx-bot` 的令牌。本文不抄任何令牌

## 做了什么

1. 看当前 `gh` 身份。它不是机器人，所以没有发评论，也没有对 opc-os 做轮询。
2. 单测覆盖评论解析、跳过机器人自己的评论、重复评论不处理两次，以及令牌只进子进程环境、不进参数。

## 命令和输出

```text
$ if [ -n "${OPC_GITHUB_TOKEN:-}" ]; then echo OPC_GITHUB_TOKEN=set; else echo OPC_GITHUB_TOKEN=unset; fi
OPC_GITHUB_TOKEN=unset

$ gh auth status
github.com
  ✓ Logged in to github.com account cursor
  - Active account: true
  - Git operations protocol: https
  - Token: （gh 自行打码。账号是 cursor，不是 briefx-bot。本文不抄令牌。）

$ gh api user --jq .login
{"message":"Resource not accessible by integration","documentation_url":"https://docs.github.com/rest/users/users#get-the-authenticated-user","status":"403"}
gh: Resource not accessible by integration (HTTP 403)
```

`plugins/opc-core` 单测里有一项通过：`GitHub 评论去重，令牌不进参数`。

## 结论

**不能在这台机器上完成**

轮询和 1 分钟内出工单都没有跑。当前 `gh` 身份是 `cursor`。用它代替 `briefx-bot` 发评论会违反「回复一律以机器人身份」的决定，所以没有发。解析和命令组装能在单测里通过。延迟 **需真机验证**。

## 下一步

在 br1efx 或运行插件的环境里只设置 `OPC_GITHUB_TOKEN`（briefx-bot），不要把令牌写进仓库。然后在 Issue 里 @briefx-bot，看 1 分钟内观察模式是否记下「本来会接单」。
