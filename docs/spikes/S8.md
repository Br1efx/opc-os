# S8 · Paseo 执行器从 @ 到等你验收

## 目的

建 Agent，在打开会话时注入 6 个工具（读取、确认、汇报、交回、关注、无关），回合结束后回报「等待」，并让一张测试工单从 @ 自动走到「等你验收」。

架构页写的钩子是 `agent.open.before` 和 `agent.turn.after`。

## 环境

- `@getpaseo/plugin` 0.14.0 的 `dist/server/lifecycle.d.ts`
- `command -v paseo` 没有结果
- 没有已登录的模型供应商，也没有 `OPC_EXECUTOR_PROVIDER`

## 做了什么

1. 对照 SDK 类型，确认能用的钩子名。
2. 看 `PluginHookAgent` 有哪些字段。`turn_ended` 的 agent 没有 `labels`；`session_open` 的请求有 `labels`。
3. 用假执行器跑适配层单测：一句话接单后应有确认和结果两条消息，工单卡停在等你验收。
4. 没有调用 `paseo` 建 Agent。

## 命令和输出

```text
$ command -v paseo || echo paseo_missing
paseo_missing
```

SDK 0.14.0 的生命周期类型里有：

```text
"agent.turn_ended"
"agent.session_open"
```

没有 `agent.open.before`，也没有 `agent.turn.after`。`PluginHookAgent` 的字段是 `id`、`workspaceId`、`parentAgentId`、`provider`、`cwd`、`title`。标签在 `PluginSessionOpenRequest.labels`。

适配层单测（`plugins/opc-core` 的 `pnpm test`，69 项通过）包含：

```text
ok - 一句话产生确认和等你验收，一共两条
ok - observe 只记录本来会接单，切到 auto 才出现工单卡
```

真 Agent 没有创建，工具回调没有被模型调用。

## 结论

**部分能**

钩子名字能对上 0.14.0。六个工具和「等你验收」两条消息在假执行器里能走通。这台机器建不了 Agent，所以「从 @ 到等你验收全自动」的真机标准没有跑成。**需真机验证**。不记成「不能」：缺的是 Paseo 和已登录的模型，不是会话打开时没有注入点。

## 下一步

在有供应商的 daemon 上设置 `OPC_EXECUTOR_PROVIDER`，用 `opc-role=executor` 和 `opc-ticket` 打开会话，确认工具列表里有那六个名字，并在回合结束后看到等待汇报。宿主自带工具能否只留给调度员和总秘书，也要在真机上看。
