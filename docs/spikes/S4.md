# S4 · 插件后台调用 paseo schedule

## 目的

架构页通过标准：能从插件创建和删除定时任务。

## 环境

- 一开始 PATH 上没有 `paseo`（`command not found`，退出码 127）
- 之后在 `/tmp/s4-cli` 安装 `@getpaseo/cli@0.14.0`，版本输出 `0.14.0`
- 临时 daemon 家目录 `/tmp/paseo-s4-home`。任务创建后马上删除，没有留到下一次触发
- 0.14.0 的 `schedule create --help` 没有 `--no-run-now`。未传 `--run-now` 时，这次创建的下一次运行是 `2026-11-01T00:00:00.000Z`

## 做了什么

1. 不连 daemon，确认子命令存在：`create`、`delete`。
2. daemon 没启动时调用 `schedule ls`。
3. 用插件 SDK 的 `execCommand`（`docs/spikes/probes/s4-exec.mjs`）创建一条任务再删除。插件源码里的同一形状在 `plugins/opc-spike-peer/server/schedule.ts`，类型检查通过，但 `index.server.ts` 没有调用它，避免插件一加载就建任务。
4. 删除后再次 `schedule ls`。

没有从已经 `running` 的插件进程里面发出这两条命令。

## 命令和输出

没有 daemon：

```text
{
  "error": {
    "code": "DAEMON_NOT_RUNNING",
    "message": "Cannot connect to daemon at home /tmp/paseo-s4-home: Daemon is not running ..."
  }
}
```

退出码 1。

不写 `--provider`：

```text
{
  "error": {
    "code": "MISSING_PROVIDER",
    "message": "Provider is required"
  }
}
```

`execCommand("paseo", ["--home", home, "schedule", "create", ...])` 然后 `delete`：

```text
--- create stdout ---
{
  "id": "1515b304",
  "name": "opc-os-s4",
  "cadence": "cron:0 0 * * *",
  "target": "new-agent:codex",
  "status": "active",
  "nextRunAt": "2026-11-01T00:00:00.000Z",
  "lastRunAt": null
}

--- delete stdout ---
{
  "id": "1515b304",
  "status": "deleted"
}

--- ls stdout ---
[]
```

脚本退出码 0。

## 结论

**PARTIAL**

`paseo schedule create` 和 `delete` 可以经 `@getpaseo/plugin/server` 的 `execCommand` 对临时 daemon 成功执行，并且删干净了。

通过标准「从插件创建/删除」：**插件进程内调用 UNKNOWN**。已加载的 `opc-spike-peer` 没有执行 `server/schedule.ts`。不记 PASS。

## 下一步

在插件的某个明确动作（不是 `contribute()` 自动执行）里调用这两个函数，对一个临时 daemon 创建再删除，并看插件日志里的命令输出。调用时要带 `--provider`，0.14.0 不要使用 `--no-run-now`。
