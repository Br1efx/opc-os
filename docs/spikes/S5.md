# S5 · 手机经 Relay 打开 5MB 图

## 目的

架构页通过标准：5MB 图在 3 秒内打开。路径是手机，经 Relay，不是本机内存拷贝。

## 环境

- 没有手机，没有配对过的 Paseo 客户端
- 临时 daemon 的 `daemon status` 里 Relay 是关的：`relay.enabled: false`，端点记录为 `relay.paseo.sh:443`
- 没有执行 `paseo daemon pair --relay`，也没有连接 `relay.paseo.sh`
- 依赖树里有 `@getpaseo/relay@0.14.0`，因为它是 Paseo 客户端的传递依赖

## 做了什么

1. 确认 PATH 上没有手机或 Relay 会话。
2. 读已安装的 `@getpaseo/relay` 0.14.0：应用帧上限 `MAX_FRAME_BYTES` 是 4294967295，单块数据 `MAX_CHUNK_DATA_BYTES` 是 65513。5MB 因此会被切成多块，而不是被帧上限直接拒绝。
3. 跑 `docs/spikes/probes/s5-frame-bytes.mjs`：在本机用 Noise `CipherState` 把 5MB 做一次加密再解密。这只测 CPU 分帧，不经过 Relay，也没有手机。

## 命令和输出

```text
$ node docs/spikes/probes/s5-frame-bytes.mjs
package @getpaseo/relay@0.14.0
frame_bytes 5242880
max_chunk_data_bytes 65513
max_frame_bytes 4294967295
chunk_count 81
wire_bytes 5244824
roundtrip_ok true
local_encrypt_decrypt_ms 80.3
note local CPU framing only; not a phone Relay transfer
```

退出码 0。80.3ms 不能用来判断手机链路是否小于 3 秒。

## 结论

**BLOCKED**

通过标准「5MB 图 3 秒内」：**UNKNOWN**。缺手机，并且这次 daemon 的 Relay 是关的。不记 PASS，也不记 FAIL。

本机分帧只能说明 0.14.0 的库允许大于 64KB 的帧，5MB 大约是 81 个块。

## 下一步

在已配对的手机上，经打开的 Relay，打开一张 5MB 图片并计时。只有那次计时能对照 3 秒。
