# S1 · monorepo 用 Git 源安装，并共用 card-protocol

## 目的

架构页通过标准：两个插件共用 `card-protocol`，并且能装上。

## 环境

- 仓库基线：`main` 的 `e742412`（D0.3 verify CI）
- Node.js v22.23.4，pnpm 10.33.4
- 本机临时 daemon：`@getpaseo/cli` 0.14.0，家目录 `/tmp/paseo-s4-home`，不是任何人的 VPS
- 新 daemon 默认 `pluginsEnabled` 不是 true。目录安装之后要先 `paseo daemon config set pluginsEnabled true`，再 `plugin reload`，插件才会从 `disabled` 变成 `running`

## 做了什么

1. `opc-core` 和探针插件 `plugins/opc-spike-peer` 都依赖 `@opc-os/card-protocol`（`workspace:*`）。
2. `pnpm install`、`pnpm typecheck`、`pnpm verify`。
3. 用 `docs/spikes/probes/s1-resolve.mjs` 解析两个插件的包路径，并调用 `hasCardShape`。
4. 把两个插件以目录方式装进临时 daemon。
5. 用一份不含 `node_modules` 的 Git 快照做 `file://` 安装。
   - 没有 `build` 时，真正 import 了共享包的探针插件安装失败。
   - 两个插件的 `paseo-plugin.json` 加上 `pnpm -C ../.. install --frozen-lockfile` 之后，同一份快照的两个插件都变成 `running`。

`opc-core` 的服务端入口引用了 `shared/card-ref.ts`，这样编译器不能把共享包跳过。Git 远程是本机 `file:///tmp/opc-os-git`，不是 GitHub。

## 命令和输出

工作区安装与检查：

```text
pnpm install
pnpm typecheck
pnpm verify
```

`pnpm verify` 的强制项通过。手机端打包和性能测量仍是 `DEFERRED`，不是通过。

两个插件解析到同一份源码：

```text
$ node docs/spikes/probes/s1-resolve.mjs
core /workspace/packages/card-protocol/src/index.ts
peer /workspace/packages/card-protocol/src/index.ts
same_realpath true
revision stub
hasCardShape true
rejects_empty false
```

目录安装在打开 `pluginsEnabled` 并 reload 之后：

```text
opc-core        status running   kind directory   path /workspace/plugins/opc-core
opc-spike-peer  status running   kind directory   path /workspace/plugins/opc-spike-peer
```

没有准备命令时，Git 安装探针插件失败（退出码 1）：

```text
Could not resolve type dependency "@opc-os/card-protocol"
imported by .../checkout/plugins/opc-spike-peer/server/hooks.ts
```

加上 `build` 之后，快照 `cf3594fac923b99a2ae42b13e9c616d443a8ac2c`：

```text
opc-core-git        status running
  remote file:///tmp/opc-os-git
  pluginPath plugins/opc-core
  node_modules/@opc-os/card-protocol -> 该 checkout 的 packages/card-protocol

opc-spike-peer-git  status running
  remote file:///tmp/opc-os-git
  pluginPath plugins/opc-spike-peer
  node_modules/@opc-os/card-protocol -> 该 checkout 的 packages/card-protocol
```

两次 Git 安装各有一份 checkout。每个 checkout 里，插件链接的是自己那份 `packages/card-protocol`。工作区里的目录安装则是两个插件指向同一条路径 `/workspace/packages/card-protocol/src/index.ts`。

## 结论

**PASS**

两个插件都引用同一份 `card-protocol`，`pnpm` 编译通过，目录安装和带准备命令的 Git 安装都在 Paseo 0.14.0 daemon 里变成 `running`。

这次 Git 远程是本机 `file://`。还没有从 GitHub 克隆安装。

## 下一步

推到 GitHub 之后，用 `paseo plugin install --ref <branch> --path plugins/opc-core https://github.com/Br1efx/opc-os.git` 再装一次。准备命令要留在清单里，否则只拷贝插件目录时解析不到 `workspace:*`。
