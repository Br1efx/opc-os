# S3 · 注入工具，并在回合结束后写时间线

## 目的

架构页通过标准：Agent 能调用插件工具，时间线出现卡片。

架构页写的钩子名是 `agent.open.before` 和 `agent.turn.after`。

## 环境

- `@getpaseo/plugin` 0.14.0 的类型声明
- 临时 daemon 0.14.0。`paseo provider ls` 里 codex 等提供方是 `loading` / 不可用
- 没有 Magpie，也没有已登录的 Agent

## 做了什么

1. 用架构页上的名字做类型检查，预期失败。文件是 `plugins/opc-spike-peer/server/legacy-names.probe.ts`，不进默认 `tsc`。
2. 按 SDK 0.14.0 的真实名字写 `server/hooks.ts`：
   - `server.before("agent.session_open")` 里 `defineAgentTool`
   - `server.on("agent.turn_ended")` 里 `timeline.append`，`kind` 为 `opc-card`
3. 默认 `pnpm typecheck` 通过，探针插件在临时 daemon 里 `running`，所以这段注册代码已被编译并执行过 `contribute()`。
4. 试着创建一个 Agent。

工具回调和 `timeline.append` 都没有实际跑到。时间线卡片没有出现。

## 命令和输出

架构页的名字对不上 SDK：

```text
$ pnpm exec tsc --noEmit --pretty false -p tsconfig.legacy.json

server/legacy-names.probe.ts(5,17): error TS2345:
  Argument of type '"agent.open.before"' is not assignable to parameter of type 'keyof PluginBeforeRequests'.
server/legacy-names.probe.ts(6,13): error TS2345:
  Argument of type '"agent.turn.after"' is not assignable to parameter of type 'keyof PluginLifecycleEvents'.
```

0.14.0 里对应的是 `agent.session_open` 和 `agent.turn_ended`。`agent.turn_ended.timeline` 在类型上标明废弃且始终为空；写时间线要用 `paseo.agents.ref(id).timeline.append`。`data` 文档上限是序列化后 64 KiB。

创建 Agent：

```text
$ paseo --home /tmp/paseo-s4-home run --cwd /tmp --provider codex "reply with the single word ok"

{
  "error": {
    "code": "AGENT_CREATE_FAILED",
    "message": "Failed to create agent: Provider 'codex' is not available"
  }
}
```

退出码 1。没有工具调用，也没有时间线卡片。

## 结论

**BLOCKED**

钩子名字和注册代码已经对上 0.14.0，插件进程也加载了。通过标准「Agent 能调用插件工具，时间线出现卡片」：**UNKNOWN**。缺一个能创建 Agent 的 provider。不记 PASS，也不记 FAIL。

## 下一步

在有可用 provider 的 daemon 上打开一个 Agent，确认工具列表里有 `opc_spike_note_card`，并在回合结束后看到 `kind: opc-card` 的时间线行。产品代码继续用 SDK 的名字，不要用架构页上的旧名字。
