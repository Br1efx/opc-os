# S7 · superagent core 在插件运行时

## 目的

`src/core`（commit `6337fc823ce20251c8de8085948165c81aaa701e`）能否在 Node ≥22.19 上用 `node:sqlite` 跑，并且原仓库 core 测试在插件能加载的同一进程里通过。

## 环境

- Node `v22.23.4`（要求 ≥22.19）
- 上游检出 `/tmp/dsh-superagent`，`src/core` 与 `packages/intake-core/src` 逐文件一致
- `@getpaseo/plugin` 0.14.0
- 没有启动 Paseo daemon。插件进程内的 `contribute()` **需真机验证**

## 做了什么

1. 用 vitest 4.1.8 跑移植后的 core 测试。测试只改了 import 路径。
2. 在 `plugins/opc-core` 的依赖解析下，同一进程加载 `node:sqlite`、`Engine` 和 `defineAgentTool`。

## 命令和输出

```text
$ node -v
v22.23.4

$ node --input-type=module -e 'import { DatabaseSync } from "node:sqlite"; const db = new DatabaseSync(":memory:"); db.exec("create table t(id int)"); console.log(JSON.stringify(db.prepare("select 1 as ok").get()));'
{"ok":1}
ExperimentalWarning: SQLite is an experimental feature and might change at any time

$ diff -q /tmp/dsh-superagent/src/core packages/intake-core/src
CORE_IDENTICAL

$ pnpm --filter @opc-os/intake-core test

 RUN  v4.1.8 /workspace/packages/intake-core

 Test Files  2 passed (2)
      Tests  144 passed (144)
   Duration  448ms

$ docs/spikes/probes/s7-plugin.sh
{"node":"v22.23.4","sqlite":"{}","tool":"opc_intake_read","engine":"Engine"}
```

探针同时打印了 SQLite 和 Transform Types 的 ExperimentalWarning。上游 core 用了参数属性，Node 只剥类型时装不上，所以探针和 opc-core 单测使用 `--experimental-transform-types`。vitest 自己会转换这些语法。

## 结论

**能**

core 测试 144 项通过。同一 Node 进程能打开 `node:sqlite`、构造 `Engine`，并定义插件工具。Paseo daemon 里加载 `opc-core` 并跑 `contribute()` 没有在这台机器上做，**需真机验证**。这不是「不能」。
