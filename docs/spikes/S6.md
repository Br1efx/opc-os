# S6 · 跨插件打开另一个插件的页面

## 目的

架构页通过标准：能或不能。不能的话，页面都留在核心插件。

## 环境

- `@getpaseo/plugin` 0.14.0 的 `PluginOpenScreenInput`
- 临时 daemon 里 `opc-core` 和 `opc-spike-peer` 都曾经 `running`
- 没有桌面或手机界面，所以没有人点过侧边栏

## 做了什么

1. 读 SDK 类型。`openScreen` 的参数只有 `screenId` 和可选的 `params`，没有插件 id。
2. 在 `plugins/opc-spike-peer/client/cross-plugin.ts` 里写了带 `pluginId` 的调用，并标了 `@ts-expect-error`。默认 `tsc` 通过，说明这行确实是类型错误；如果 SDK 以后收下 `pluginId`，`@ts-expect-error` 会让类型检查失败。
3. 对照 0.14.0 公开文档：`openScreen` 打开的是本插件注册的页面，未知的 screen id 会失败。`PluginClientContext` 上没有 `openPlugin`。
4. 没有在界面里从探针插件点进 `opc-core` 的「一人公司 OS」。

## 命令和输出

`pnpm --filter opc-spike-peer typecheck` 通过，其中包含：

```ts
export function openOtherPluginScreen(openScreen: PluginSidebarItemProps["openScreen"]): void {
  // @ts-expect-error S6：类型只接受本插件的 screenId，不接受另一个插件的 id
  openScreen({ screenId: "home", pluginId: "opc-core" });
}
```

`openScreenAcceptsPluginId` 被赋值为 `false`。如果 `"pluginId"` 变成 `PluginOpenScreenInput` 的键，这个赋值会失败。

没有界面会话，所以没有运行时的打开结果，也没有截图。

## 结论

**BLOCKED**

运行时「能不能打开另一个插件的页面」：**UNKNOWN**。不记「不能」，也不记 PASS。

类型和 0.14.0 文档目前只提供本插件的 `screenId`。在桌面端做过一次真实点击之前，产品页面继续放在 `opc-core`，不依赖跨插件跳转。`opc-spike-peer` 只是这轮探针，不是外围产品插件。

## 下一步

在同时装了两个插件的桌面端，从探针插件调用 `openScreen({ screenId: "home" })`，看它打开的是谁的页面；再试任何文档化的跨插件入口。那一次结果才决定页面是否必须全留在核心插件。
