# 0005 · D3 的卡片墙和 Bases 子集

- 状态：已接受
- 日期：2026-11-01
- 相关：[0002](0002-d1-shell-and-cards.md)、[0004](0004-d2-notes.md)
- 协议修订号已由 [0006](0006-d5a-tasks-workflows.md) 加到 `d3`。本记录的视图和卡片动作仍然有效；「转成任务」从只改类型改为进入开发流。

## 背景

D1 把卡片收成五种类型，状态仍是任意非空字符串。D2 的笔记落在工作区 Markdown 上，没有卡片墙。架构里的卡片墙要有四个视图、五个预置视图、卡片动作、侧栏上的「等你处理 N」，以及一个只覆盖筛选、排序、分组的查询引擎。

卡片目录和 D2 笔记同库，但只使用固定路径，不做多端同步。M2 的待办、进行中、待审、完成留给后续的任务流。Agent 观测台这次不卸载。

## 决定

1. 卡片仍是 `@opc-os/card-protocol` 的字段，不另造格式。协议修订从 `d1` 加一，记为 `d2`。新增类型 `decision`（决策）。状态只允许 `inbox`、`incubating`、`active`、`settled`、`shelved`、`archived`。这是 §1.2 的一段生命周期，末段拆成搁置和归档两列，这样从搁置改成归档会换栏。
2. §1.2 的笔记种类在写入前换成协议类型。协议的 `type` 不接受中文名。问题没有对应种类，留给要人拍板的卡，例如回合结束后的卡，以及网关的成本熔断卡。熔断卡原来的自由状态 `alert` 收进 `inbox`，否则升版后 `parseCard` 会拒绝它。

   | §1.2 | 协议 type | 界面 |
   | --- | --- | --- |
   | 想法 | `topic` | 选题 |
   | 随笔 | `material` | 素材 |
   | 资料 | `asset` | 资产 |
   | 链接 | `material` | 素材 |
   | 视频 | `material` | 素材 |
   | 提醒 | `task` | 任务 |
   | 复盘 | `decision` | 决策 |

3. 卡片目录是 `/home/br1efx/notes/cards/`。每张卡是一个 Markdown 文件，前言是这些字段，另可带 `project`。视图定义在 `/home/br1efx/notes/cards/_views/`，YAML 子集或 JSON。缺省的九个文件会补上，已经改过的文件不覆盖。
4. 查询引擎在 `shared/bases.ts`，是纯函数，不引用 Obsidian。支持的筛选是等于、不等于、包含、为空、日期范围，以及并且、或者。日期范围可以写绝对时间，或 `$now`、`$todayStart`、`$todayEnd`、`$now-7d`、`$now+7d`。「今天」按协调世界时。排序可以多字段。分组是单个字段。不支持公式、`this`、文件链接、正则和视图继承。
5. 四个主视图是等你处理、状态看板、业务线分栏、时间线。五个预置视图是收件箱、想法墙、待拍板、近期提醒、按项目。等你处理和收件箱的预置筛选都是 `status=inbox`，可以各自改文件拆开。近期提醒用类型 `task`，因为提醒映射到任务。业务线取 `project`，预置三列：父亲 AI 芝麻馆、Build in Public、插件开发。改状态或项目后，分组结果换栏。
6. 回合结束写入收件箱。SDK 0.14.0 没有名为 `agent.turn.after` 的钩子，实际注册 `agent.turn_ended`。人手动新建走同一个 `writeCard`。定时任务、外部投递和一键收集以后也调用它，这次不接来源。刷新间隔 15 秒，短于一分钟。
7. 同意、打回、指派会离开收件箱。打回必须有理由。问题和决策在同意后进入已沉淀，其他类型进入推进中。指派把负责人改成指定的 Agent 并进入推进中。归档进入 `archived`。转成任务只把 `type` 改成 `task`，并写上 `handoff: d5-task`，不跑工作流。同意、打回、指派由界面用 `usePaseo().agents.ref(id).send` 把中文指令发给 Agent。负责人不是 Agent 时，卡片仍然更新，但不发送。
8. 侧栏入口的文字是「等你处理 N」，N 用等你处理这张视图的数量。数量大于 0 时旁边有一个圆点。处理后重新读取，数量下降。非法卡片显示「格式错误」和字段问题，不参与筛选。
9. `m2-card-wall` 的权限清单改为启用，只声明上述目录和 `_views/` 的读写，不联网。界面按钮始终可见，不依赖悬停。手机和电脑走同一组 RPC。

## 后果

没有在 Paseo 真机或手机上点过同意、打回和侧栏。钩子要等宿主发出 `agent.turn_ended` 才会写卡。目录在主力机上，这台检查机不会去创建 `/home/br1efx/notes/cards/`。

权限扫描仍然不能证明服务端只访问了清单里的路径。`server/` 里的文件系统 API 算在外壳上，外壳原本就声明了 Markdown 读写。越界路径由代码拒绝。

`pnpm verify` 不测量手机打包和性能。这两项仍是未执行，不是通过。registry 的提交指针这次不改。
