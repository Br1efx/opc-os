# 0006 · D5a 的任务字段、工作流和卡住阶梯

- 状态：已接受
- 日期：2026-11-01
- 相关：[0005](0005-d3-card-wall.md)

## 背景

D3 的卡片协议修订是 `d2`。任务卡还没有目标、验收、截止、依赖、步骤和工作流。卡片墙上的「转成任务」只改类型，并写 `handoff: d5-task`，文案说明工作流还没接上。待办、进行中、待审、完成留给这一段。

D5 拆成 D5a 和 D5b。这一决定只覆盖 D5a：任务字段、三条工作流、完成定义、一键起任务、卡住阶梯、定时命令降级，以及进度、会话归档和历史搜索。不实现 opc-intake，不做 S7–S9，不自动合并，也不改 registry。

视频流要按《父亲工作台 v2》走完整流程。需要外部账号或真机的节点标「需真机验证」，不在本仓库里假装已经跑过。

## 决定

1. 协议修订从 `d2` 加到 `d3`。`type=task` 可以带 `goal`、`acceptance`、`due`、`dependsOn`、`workflow`、`stage`、`failCount`、`ladderLevel`。`owner` 和 `evidence` 沿用公共字段，不另造。这些字段都可以不出现，所以旧的 `d2` 卡仍能读过。非任务卡带上这些字段则拒绝。`stage` 是工作流步骤，和生命周期 `status` 不是一回事。`failCount` 和 `ladderLevel` 允许数字文本，读入时转成数字。
2. 进入待验收或完成之前必须至少有一条 `evidence`。没有就拒绝，并把卡上的缺口写成「缺证据」，步骤停在原地。
3. 工作流模板是仓库里的三份 YAML：开发流、视频流、内容流。服务端启动时把缺的模板种到 `/home/br1efx/notes/cards/_workflows/`，已有文件不覆盖。之后每次读取都解析磁盘上的文本，改 YAML 即生效。非法模板用中文说明原因，不启动该条。步骤种类是起步、自动、门禁、等人、待你验收、完成。第一步的进入条件只能是开始。
4. 卡片墙保留「转成任务」，默认走开发流。另有「从模板起任务」。按步骤角色用 `usePaseo` 先唤醒、没有再新建，并送出第一句话。新建时工作目录是 `/home/br1efx/notes`，供应商标成 `codex`，并打上 `opc-role`，避免清到没有标记的会话。供应商要换成这台机器上已登录的，仓库里不写钥匙。
5. 架构里的 `agent.turn.after` 在 SDK 0.14.0 上不存在。和 D3 一样，实际钩子是 `agent.turn_ended`。回合结束先认领当前任务并推进步骤；没有对应任务时，才按 D3 的方式另写一张问题卡。用户点的动作由界面发送。无人值守的下一步由服务端的 `context.paseo` 发送。送不出去就在卡上留下待发送，卡片墙可以再送一次。这一步需要真机。
6. 失败来自打回、门禁没过，或 Agent 用工具自报失败。第一次只计数。第二次把负责人改成攻坚开发。再失败交给会诊，会诊结束不自动往下走。再失败生成 `type=decision`、`status=inbox` 的决策卡，标题以「请拍板：」开头，出现在「等你处理」。每一级都写进任务时间线。`failCount` 是累计次数，不是每一级重新数两下。攻坚做成功后，卡住级别回到 0，失败次数保留。
7. Agent 可以记证据、问一个问题、自报失败。记证据不推进步骤。已经有未回答的问题时，完成的回合不推进。问题格式是 `human_action`，一次一个。自报失败后，同一回合结束不再计第二次。
8. 定时任务不调用守护进程。`usePaseo` 没有创建定时任务的方法。探测里对临时守护进程的创建会变成已启用，已加载插件里能不能调用仍不清楚。因此只生成可复制的 `paseo` 命令，本地记录 `enabled: false`，命令不含立即运行。时区是 `Asia/Shanghai`，`--expires-in 30d`，工作目录 `/home/br1efx/notes`。心跳要在已有 Agent 会话里执行，插件建不了，同样只给命令。预置七条：07:30 选题雷达、09:00 早间简报、12:00 与 20:00 数据回收、23:30 夜审、周日资产周报、周日周更。只创建记录，不默认启用。手动执行后要自行暂停。需真机验证。
9. 进度、会话清理和历史搜索按行为重写，不拷贝旧插件代码。进度是进度条、卡点和至多一个问题。清理先预览，只归档带 `opc-role` 或 `opc-schedule` 标记、或已经登记的会话，调用 `archive()`，不删除。历史只读，搜得到已归档。
10. 卡片墙增加预置视图「任务」（按 `stage` 分列）和「卡住了」（`ladderLevel` 大于等于 1）。筛选增加大于等于，避免把缺字段当成已经卡住。
11. `m4-tasks` 的权限清单改为启用。读写 `/home/br1efx/notes/cards/`，以及 `_workflows/`、`_sessions/`、`_schedules/`。不联网。界面开关关掉时，任务动作退回只改类型，其余任务接口说明已关闭。

## 后果

没有在 Paseo 真机上点过起任务、派工、回合推进、归档或定时命令。`codex` 只是命令和创建参数里的占位，真机要换成已登录的供应商。视频流里选题、风格、配音、静帧、动画、配乐、上传、发布和数据监控，以及内容流的数据回收，都标了需真机验证。

服务端的文件系统 API 仍算在外壳上。清单写了路径，扫描器不能证明只访问了这些路径。越界由代码拒绝。

D5b 的调度员、工单隔离和自动合并不在这次。GitHub 机器人账号也不在这次。
